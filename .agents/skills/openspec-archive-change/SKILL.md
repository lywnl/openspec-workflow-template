# 同步规范与归档

按需读取 [工作流规则](../../shared/openspec/workflow-policy.md) 和 [归档与证据规则](../../shared/openspec/verification-evidence.md#正常完成归档)，复用当前上下文中有效的规则，不反复查帮助或扫描无关归档。

## 正常路径

1. 明确项目根、变更、核验方式和归档授权，从变更 `.openspec.yaml` 读取 workflow_profile，核对报告、检查点及助手 --profile 一致。候选不唯一时先询问。读取当前验收结论、必要评审与任务，非 Ready for Archive 或有阻塞时停止正常归档；目录存在或任务勾选不能代替验收。
2. 读取实际 schema 规格指令、增量及对应正式规范，确定完整合并内容，保留无关要求。确认目标为 changes 根下 archive 的 `YYYY-MM-DD-<名称>`，已有日期不重复添加，目标已存在则停止。出现未获确认的规范冲突或范围变化时先询问。
3. 有规范增量且使用 machine 时，在 `.codex/<变更名>/` 准备完整目标文件及同步计划，用 `--sync-plan` 执行 `prepare`。该命令已核验规划、验收、任务及清单，不在外部重复执行相同机器检查；AI 仍须判断报告结论及合并语义。
4. 写入前运行 `check`，只处理 pending_targets，内容取预登记版本；全部目标写完运行 `synced`，由工具检查内容、非同步输入并执行真实规范校验。无需在 synced 前再补一轮 check、cmp 或规范 CLI 校验。
5. 移动前运行 `check`，整体移动到预登记目标，不改写原规划或验收记录。以归档路径运行 `archived`，工具核验目录、规范、原记录和证据，运行实际 CLI 校验及活动列表检查，并自检落盘后的最终报告。成功返回即为本轮最终机器结果，不再追加同等外部 check、shasum 或 JSON 摘录。

已有归档授权时连续执行，不主动在 prepared 暂停；用户明确要求分段测试时在指定步骤停止。工具不负责写规范或移动目录，也不执行提交、推送或部署。不要在手动同步后再盲目调用可能重复同步的 CLI archive。

无增量规范不创建空检查点：machine 核对 check-verify，manual 按共享清单比较，执行当前 CLI 支持的适用校验，记录无需同步、活动与归档路径及原规划和验收记录的哈希。整体移动后核对目标存在、源目录消失、原记录字节未变化、活动列表不再包含变更，再补记真实结果，失败不能宣称完成。原记录中的活动路径保留历史含义，不重新生成验收结果。manual 有同步时按共享规则保存前后内容、输入基线及实际结果，不生成冒充机器结果的记录。

## 恢复与异常

- 已有检查点先 check，按当前阶段继续剩余动作，不重新 prepare，不根据现状重建 expected 或通过记录。
- prepared 只允许预登记的前后状态；synced/archived 只允许目标内容。源目标并存、额外文件变化、记录损坏或内容冲突时停止，报告差异及处理条件。
- check 指出校验尝试中断或报告缺失时，在当前合法路径重试 synced/archived；工具重查基线并实际运行命令。基线不匹配时不能靠重试、降级 manual 或重新登记来消除差异。
- CLI 校验失败保留记录和当前文件，不移动、不自动回滚；移动完成但最终核验失败时明确“已移动，核验未完成”。出现需要改变已确认方案的处理方式，等待用户确认。

## 取消与输出

只有用户明确要求取消、放弃或替代时，记录 Cancelled/Superseded、原因、未完成事项及残留状态，在授权下归档。不同步未完成增量，不自动删除已同步规范或业务数据。

最终只说明同步内容、归档路径、检查结论和剩余问题；失败时给出具体原因和下一步。完整哈希、内部阶段字段及命令输出保存在记录中，用户要求或排错时再展开。
