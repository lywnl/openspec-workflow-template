# 同步规范与归档

读取本次必要的 [工作流规则](../../shared/openspec/workflow-policy.md) 与 [归档规则](../../shared/openspec/archive-workflow.md)。已读且未变化的内容直接复用；manual 才补读 [人工核验](../../shared/openspec/manual-verification.md)。

## 进入归档

1. 确认项目、具体变更和归档授权，按共享元数据兼容规则解析等级，核对报告、检查点与助手 --profile。候选不唯一时询问。
2. 检查真实验收结论、任务及阻塞。非 Ready for Archive 停止正常归档；取消／替代仅按用户明确请求走共享取消路径。
3. 已有检查点先 check，按记录继续剩余动作，不重新 prepare，也不根据当前文件重建 expected。
4. 首次归档读取实际 schema 及规范增量，准备完整合并内容，保留无关要求；目标使用 changes/archive 下的日期加变更名，目标已存在或规范冲突未解决时停止。按 [归档导航规则](../../shared/openspec/archive-workflow.md#归档导航与原始证据) 检查移动前后的 Markdown 引用，覆盖变更目录、README 及查找到的其他入口。

## 执行与恢复

- 有增量规格或必要导航更新的 machine：按 [检查点步骤](../../shared/openspec/archive-workflow.md#同步检查点与中断恢复) 执行 prepare → 写入前 check → 仅写 pending_targets → synced → 移动前 check → 整体移动 → archived。规范内容由同步计划登记，导航内容由工具按最终目录计算；准备文件在项目 `.codex/`，工具本身不写目标文件或移动目录。
- 无增量规格：先用 links 检查是否需要导航更新；需要时使用非空导航检查点，不虚构规格。两者均不需要时按 [无需同步的路径](../../shared/openspec/archive-workflow.md#正常完成归档) 核对验收、实际任务和适用 CLI 校验，记录原记录哈希及路径后整体移动，完成移动后核验；不能因 fast 就跳过实际存在的规格增量。
- manual：登记同样的原记录、前后内容、非同步输入及真实校验，不生成冒充机器的记录。
- 原评审、验收报告、JSON 和原始证据保留原字节；仅对预登记的普通文档更新必要链接地址，不能顺带改正文或任务状态。受保护文件的历史链接由 archive-record 提供当前入口并说明未直接改写。prepare/synced/archived 已执行的等价检查不在外部重复。
- 失败或中断保留实际状态。合法基线下重试对应阶段；额外改动、源目标并存或记录损坏先报告，不能降级核验方式或重建通过记录来消除差异。移动后核验失败明确写“已移动，核验未完成”。

已有归档授权时连续完成，不主动停在 prepared；用户要求分段操作时遵守指定边界。不要在手动同步后再调用可能重复同步的 CLI archive。

## 输出

说明同步内容、归档路径、实际核验结论、导航更新与保留的历史引用及剩余问题；不能将有限范围的文件链接检查表述为全项目所有链接均有效。取消记录用 Cancelled/Superseded，保留未完成事项，不同步未完成规范或自动清理残留代码。本入口不提交、推送、部署或修改真实业务数据。
