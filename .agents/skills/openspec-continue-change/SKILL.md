# 继续或修订规划

读取 [工作流规则](../../shared/openspec/workflow-policy.md) 和 [来源规则](../../shared/openspec/sources.md)，需要补充项目事实时使用 [上下文发现](../../shared/openspec/project-context.md)。复用已读取且未变化的内容。

## 选择模式与基线

1. 明确变更。用户未给名称且上下文无法唯一确定时，使用 `openspec list --json` 展示候选并澄清。
2. 按共享的元数据兼容规则解析 `.openspec.yaml` 的等级；运行 `openspec status --change "<变更名>" --json` 获取实际 schema、路径和依赖。缺失、冲突或解析失败先处理；fast-change 只生成 proposal/tasks，已有变更不能因标记 fast 删除其他必需产物。
3. “继续生成”使用生成模式；“修改、补充、调整”使用修订模式；混合请求先修订已存在内容，再按授权范围生成缺失内容。
4. 按 [探索与规划交接](../../shared/openspec/workflow-policy.md#探索与规划交接) 复用已确认范围和行为；没有探索记录时承接明确需求与现有规划，不要求补做 explore。候选建议不得自动成为必需需求或任务。影响范围、行为、兼容性、成本或验收的新决定才针对性澄清；普通工程选择记录理由与假设，不逐段索要确认。仅要求“下一步”默认生成一个产物，要求“全部规划”则连续生成到依赖齐备。

## 生成模式

1. 找到下一个 ready 产物，获取 `openspec instructions <产物> --change "<变更名>" --json`。
2. 读取指令、规则、模板和磁盘上的实际依赖文件，结合相关实现、测试与正式规范填充内容，不将 context/rules 原文复制进产物。来源已变化时重新核对；探索结论与现有文件冲突时明确指出并处理，不能用旧聊天静默覆盖当前产物。探索未展开的技术细节在对应产物中补全，不凭空推导新的业务需求。
3. 按 CLI 解析的具体路径写文件，保留机器识别的结构标记，正文使用中文。glob 路径须按能力选择具体文件，不能当成文件名。
4. 保存后检查内容及受影响依赖，复查状态。默认完成一个就绪产物后停止；specs 需要多个能力文件时保持该产物完整并说明文件集合。用户要求完成全部规划时，持续处理 schema 所需的传递依赖；不因每次保存重复全量规划校验。
5. 仅在 schema 或该产物指令明确允许时省略产物，并报告原因；不能为尽快进入 apply 自行省略规格或测试任务。

## 修订模式

1. 读取受影响产物及其上下游，说明修改的需求或决策。已有明确修改指令时直接在授权范围内修订，不逐文件重复请求批准。
2. 检查规格、设计、任务和来源是否一致，修正实际受影响的内容；新发现会改变目标或风险的决策需澄清。
3. 保留已有实施状态和证据，不能因改写文档把未验收任务勾选。任务范围变化时明确哪些旧完成结论需要重新验证。
4. 不再复用失效的规划评审或验收记录；需要新产物时回到生成模式。风险升级按 [同目录补全流程](../../shared/openspec/workflow-policy.md#schema-与范围升级) 调整等级、schema 和 skip_specs，并补齐来源及规划；不能新建另一变更来丢弃旧状态。

## 内容约束

- proposal 说明目的、范围、非目标、影响及 Source Inputs 登记表，按来源规则承接用户原文、补充决定及替代关系；无外部材料仍须登记对话或代码依据，不编造来源。standard/strict 缺少来源记录时仅补录可核实内容。
- specs 描述可观察行为和场景；design 承接技术决策、兼容性与适用风险；tasks 包含依赖、实现范围及验证方法。使用需求/场景名称和任务编号引用已有内容，避免全文重复，不增加只为转述规划的文档。
- 使用 Markdown tasks 时只把必需执行工作写成 checkbox。其他任务格式沿用 schema 的真实状态字段与完成条件。条件任务明确触发条件；不适用时记录原因并移出必需清单，经必要规划复审后再实施，不能简单标记完成。
- tasks 正文只描述任务范围、依赖和完成条件，当前状态由 checkbox 与真实证据表达。不写“当前所有任务尚未执行”等随实施过时的断言；“本轮完成后停止、下一入口”等提示放在会话回复中。已有冻结任务中的过时说明不能顺手改写，按修订模式核对受影响基线。
- tasks 保留实现及具体测试、检查；正式验收结论、验收指纹和归档写为交付条件，不设为验收通过前必须完成的循环任务。已有此类任务时明确修订并按规划规则复审，保留真实完成状态。
- 自定义 schema 的内容以其指令为准；不要强行套用标准文件名。source 检查最终由 review-change 聚合收口。

输出本次生成/修订文件、关键决定、未决项和下一步，然后停止。最后一份规划完成后也只提示 `openspec-review-change`，未经明确授权不自动评审；用户明确授权的连续流程按其范围推进。本入口不修改业务代码。
