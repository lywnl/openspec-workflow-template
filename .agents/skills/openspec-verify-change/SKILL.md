# 核验实现

读取 [工作流规则](../../shared/openspec/workflow-policy.md) 和 [验收证据规则](../../shared/openspec/verification-evidence.md)。本入口检查实现，不重新给规划文案打分。

没有实现、只需判断方案能否开始编码时使用 review-change。本入口复用有效规划评审及实施阶段的需求映射和运行证据；只补核缺口、差异及失效项，不重复生成一份规划评审或整套实现交接报告。

## 执行

1. 确认变更、profile、源码与规划根，读取当前任务、规划评审及核验方式。machine 执行 `check-plan`，manual 按共享步骤重新枚举并比较规划清单；基线失效时先修正规划交接。
2. 识别每个必需行为、场景和任务对应的实际代码、测试及运行证据；非代码变更使用相应的实际验证。
3. 检查完整性、正确性、设计一致性、失败路径、兼容性和项目工程约定；strict 覆盖所有声明的高风险边界。
4. 核对相关代码、配置与证据是否属于当前基线。旧结果仅在其全部相关输入未变化且环境前提仍成立时复用；涉及真实外部状态时按项目要求重新确认或执行，不用缓存掩盖过期。
5. 运行尚缺的必要验证，先核实外部服务、费用与环境操作授权。无法执行时保留阻塞，不将 skip 或仅收集用例计入通过。
6. strict 取得当前实现的独立代码质量评审，standard 根据实际争议和风险按需增加；记录发现与修复后的验证。
7. 输出 `reports/verification.md`，fast 可用共享短格式；给出 `Ready for Archive`、`Needs Work` 或 `Not Ready`，每个发现关联具体任务/需求和实现位置。
8. 只有 Ready for Archive 时绑定当前代码、任务、报告及原始证据。machine 核对 `reports/verification-manifest.json`（已有有效清单可复用），运行 `evidence_manifest.py` 后将清单纳入 `record-verify` 输入，再执行 `check-verify`；manual 按共享步骤保存并比较清单，不强制运行 Python 助手，报告人工核验范围与限制。其他结论不能保存为通过记录。

## 回退与边界

- 实现缺陷交给 apply-change 修复；验收口径或设计缺陷交给 continue-change 修订，再 review。
- 如果用户已授权持续修复，可以按上述入口继续推进；不得为了结束验收擅自扩大范围。
- 测试通过不等于已获部署许可，证据助手通过也不证明测试内容真实有效。
- 输出实际验证范围、失败或未运行项、独立评审状态及下一步，不隐去环境限制。
